# AWS Cloud Integration Terraform Module

This Terraform module enables the registration of AWS accounts or organizations with CrowdStrike Falcon Cloud Security. The module supports both single account and organizational deployments, with flexible options for AWS authentication.

## Overview

The registration process consists of two main parts:
1. Creating the account registration in Falcon Cloud Security
2. Deploying required resources in AWS

While the Falcon registration remains consistent, AWS resource deployment can be configured through different authentication methods to suit your security requirements and operational needs.

### Prerequisites
#### 1. Terraform >= 1.5.0
  - Download from: https://www.terraform.io/downloads.html
  - Installation guide: https://learn.hashicorp.com/tutorials/terraform/install-cli
#### 2. Valid CrowdStrike Falcon API credentials
  - Credentials are usually generated by UI wizard along with this module.
  - Create an API client in Falcon console: https://falcon.crowdstrike.com/support/api-clients-and-keys
#### 3. Appropriate AWS credentials/access
  - More about provider authentication and configuration:  https://registry.terraform.io/providers/hashicorp/aws/latest/docs#authentication-and-configuration

## Deploy
1. Configure AWS provider
2. Set required environment variables
```shell
export TF_VAR_falcon_client_secret=<your client secret>
```
3. Initialize and apply Terraform:
```shell
terraform init
terraform plan -out=tfplan
terraform apply tfplan
```

## Destroy
To teardown and remove all resources run:
```shell
terraform destroy
```

## Organization deployment
When deploying to organization child accounts, do this for each child account:
* duplicate `accounts.tf` file and initialize the aws providers
* rename the child modules to be unique
* update `use_existing_cloudtrail = true` for all child modules
* use the new aws providers in the child modules
* add the child modules to `data.crowdstrike_cloud_aws_account_validation.fcs_account_validation.depends_on` in `main.tf`
* for agentless scanning cross-account scanning, make sure to apply the module first in the chosen host account, and apply in target accounts only once the deployment in the host account has completed
